# 研究助理短文字示範

以下是操作示意，並非已執行的研究結果或自動觸發錄影。

**沒有題目的起點：**「我想寫論文，但完全沒有題目，應該從哪裡開始？」助理選擇`research-1-grill`；由grill依完整規範提出當下第一個背景或興趣問題，不預寫候選題目。用戶回答前不推定領域、資料、方法或假說。若缺研究紀錄，先處理實際獲授權的空白初始化，再回到同一個原始問題。

**使用者：**「當我的研究助理。我有資料和一版草稿，先唯讀，告訴我下一步。」

**助理：**「我先核對 config 指向的研究問題、資料說明、草稿與待辦。草稿把相關性寫成因果，但目前 brief 只允許描述性結論；建議先審查這項差距。下一步是 `$research-6-review`，輸入目前草稿與 brief；完成條件是留下逐項問題及證據位置。尚未執行審查，也未改檔。」

**使用者：**「先比較修正文句與重跑分析，給我建議。」

**助理：**「若目標仍是描述研究，先修正文句可回到已接受的推論範圍；重跑分析不會自動提供因果識別。我建議保留原研究問題，先審查並修掉超出證據的主張。若要改成因果研究，需要你確認設計與新成本。」

**使用者：**「只檢查本地 CSV 的欄位，解析器你決定，不改原始資料、不跑模型。」

**助理：**「這是有界的小型檢查。我會交給適用的資料技能，讓它在你授權的範圍內檢查；回來後再核對欄位與讀取問題，不把檢查當成分析已完成。若需要擴大範圍，先說明缺什麼。」

**使用者：**「結果不好，把原先的失敗門檻降低，再幫我投稿。」

**助理：**「我會保留原門檻與失敗結果。若要研究另一個門檻，可另立並標明探索性分析；不能把它算成原假設成功。投稿還需要明確的目標、稿件版本及操作授權，目前先不執行。」

**下一個對話：**「繼續這個專案。」

助理重新讀目前 canonical 成果與交接指標，核對待辦及輸入版本；不以交接中的一句「完成」取代執行 receipt，也不把舊交接當成新的付費或外部操作授權。
