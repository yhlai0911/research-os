# Research OS 提示詞範例

以下範例刻意包含目的、受眾、限制與目前狀態。請替換方括號內容，不需要保留所有欄位。

## 走主線（第一次使用建議這條）

主線六步，每步跑完會告訴你下一步是什麼然後停下來。第一步：

```text
/research-1-grill

我想研究「[主題或現象]」，最後要形成一份[研究計畫／企劃案／論文藍圖]。
受眾是[誰]，用途是[投稿／申請經費／校內審查／決策]。
目前只有方向，沒有完整文獻、資料與方法。
限制：[免費資料、研究期程、地區、排除的方法等]。
```

它收斂後會說明這個想法已經可研究，並指向下一步。接著依序：

```text
/research-2-brief      把已經談定的內容鎖成一份研究契約
/research-3-falsify    先講清楚什麼結果會推翻這個設計
/research-4-tasks      拆成可獨立驗證的研究任務
/research-5-run        認領並跑第一個任務
/research-6-review     用期刊審稿人的角度攻擊自己
```

任何時候想確認位置：

```text
/research-status
```

## 從模糊題目開始（自動駕駛）

```text
/research-auto

我對「[主題或現象]」有興趣，希望最後形成一份[研究計畫／企劃案／proposal／論文藍圖]。
受眾是[誰]，用途是[投稿／申請經費／校內審查／決策]。
目前只有方向，沒有完整文獻、資料與方法。
限制：[免費資料、研究期程、地區、排除的方法等]。
請先判斷最關鍵的不確定性，能查證的事實由你查證；
只有真正需要我決定時才一次問一個問題。
```

## 檢查題目值不值得做

```text
/research-triage

題目：[題目]
我認為的貢獻：[目前想法]
可用資料：[已知資料]
請不要替題目辯護。從 closest literature、意義、識別、
資料可行性與可反證性判斷應該 kill、repair、pilot 或 advance。
```

## 逐題釐清研究構想

```text
/research-1-grill

我的初步想法是：[想法]
最後要形成：[成果]
請像研究指導教授一樣逐題追問，但每次只問一個會改變下游設計的問題。
每題要附你的建議及採用該建議的代價。
```

## 修復已有研究計畫

```text
/research-auto

這是我現有的研究計畫：[貼上內容或提供檔案]
不要從頭重做，也不要改掉已接受的選擇。
請先找出最可能導致退稿或無法執行的 load-bearing 問題，
修補根因後再更新受影響的 artifacts。
```

## 從方程式或外部理論發展研究

```text
/research-auto

我想把[方程式／理論／其他領域概念]用於[研究領域]。
請先確認每個符號、單位、機制與經濟意義，
搜尋既有應用，並設計能和普通替代模型區分的可拒絕限制。
若只是換名稱或物理類比，請直接指出，不要包裝成新理論。
最後形成一份[研究計畫／paper blueprint]。
```

## 資料先行

```text
/research-auto

我手上有這份資料：[資料說明或路徑]
請先檢查欄位語義、頻率、涵蓋期間、授權、缺失與時間對齊，
再提出這份資料真正能支持的最強研究問題。
不要先決定結論，再反向挑變數。
```

## 形成學術研究計畫

```text
/to-plan

把 current Research Brief 轉成一份可送審的學術研究計畫。
受眾：[審查單位]
格式：[章節或頁數要求]
語言：[繁體中文／英文]
研究方法必須逐一對應研究問題、estimand、資料與反證條件。
尚未查證的主張保留原狀，不得補猜。
```

## 形成企劃案或補助 proposal

```text
/to-proposal

把 current Research Brief 轉成[計畫類型]企劃案。
受眾：[審查者或決策者]
決策標準：[影響、可行性、創新、預算、風險等]
請區分已驗證事實、研究者選擇、估算與尚待核准承諾。
```

## 形成論文

```text
/to-paper

以 current Research Brief、claim ledger、實證結果與 review 為依據，
產出[期刊／領域]風格的論文。
若沒有已執行結果，只能建立 paper blueprint、方法、命題、
預期表格與待驗證事項，不得編造係數、顯著性或穩健性結果。
```

## 跨 session 交接

```text
/research-save

請為下一個 session 建立可驗證交接：
列出 current artifacts、已接受決策、blocked claims、未完成 gates、
下一個 frontier，以及每個 pointer 的 readback。
不要以聊天摘要取代 canonical artifacts。
```
